## Decisions

- **No functional change.** No entity attribute, process step, use case flow, state, or acceptance
  criterion changes. Protocol step 5 therefore produces no user stories.
- **Entities** get one page each in `domain_model/entities/`, holding the description and the
  attribute table. The class diagram stays the single description of the relationships.
  `domainModel.md` keeps the diagram and links every entity.
- **Actors** get one page each in `use_case/actors/`, holding the type, the description and the
  system access. `actorDescriptions.md` links every actor.
- **Sources follow the derivation chain of the conventions:** an entity derives from the domain
  model; the business process from the domain model; the use-case diagram from the business
  process; an actor from the business process; a use case from the use-case diagram, the business
  process and the domain model; the state chart from its entity and the use cases that trigger its
  transitions; the story map from the use-case diagram, the domain model, the business process and
  its use cases; a user story from the story map and the use case it traces to.
- Each source is written with a **bundle-absolute path** (`/use_case/useCaseDiagram.md`), so the
  same value resolves from any file (OKF v0.2 §6.2), and an **id** in kebab-case, which footnotes cite.
- Artifacts this change created or restructured also cite this change request as a source.
- **`generated:`** is `by: jarvis/1.0` — the agent and this version of its instructions, not a
  model. `at` is the last meaningful change: the time this change was applied, for every artifact
  whose body it changed, and otherwise the last commit that changed the artifact.
  **Assumption:** the existing artifacts were written by Jarvis, as this repository describes.
- **`verified:`** is never written by Jarvis. The owner records an approval with `make verify`.
- **Tags** are the domain entities an artifact names outside its headings, plus, on a user story,
  its release row (`r1-walking-skeleton`, `r2-core-transactions`, `r3-robustness-security`) and its
  KANO class (`kano-basic`, `kano-performance`, `kano-attractive`).
- **`content/log.md`** is generated from the change log by `make generate`; the change log stays the
  only place a version is written.
- **Version v1.3**, following v1.2 on `main`. **Assumption:** if the `beverage-release` branch, which
  carries v2.0 – Order Coffee, is merged first, this change becomes v2.1.
