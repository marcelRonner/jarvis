# CR-1.4 – File Open Knowledge Format Assessments

A documentation change requested on 2026-09-13. It changes no behaviour of the ATM system.

---

## Request

Requested by the owner on 2026-09-13. The result of `/okf-check` should be saved in the content
instead of existing only in the chat — the first assessment, which led to CR-1.3, survives only in the chat transcript.
The owner proposed saving it in Sources with a log entry that links to it, and asked for a better
idea if there was one. After seeing the proposal below, the owner added two requirements:

- Every check in an assessment shows a short description of what it checks next to its ID, so the
  reader no longer has to switch to the check register to understand a row.
- The checks are grouped visually: the mandatory ones first, then one table per kind of check,
  instead of one large table with mixed entries.

## Analysis

- **Sources** is the right home. An assessment is what a change request derives from, so filing it
  there lets the next change request cite it, and footnote every check it fixes.
- **The log** cannot take a hand-written entry: `content/log.md` is generated from the change log
  and overwritten by `make generate`. The change log cannot take the assessment either, because it
  lists versions and an assessment changes no artifact. The generator has to read the assessments
  as a second input.
- **The check register** has IDs and full wordings but no short names, so a readable description
  would be invented afresh on every run, and two runs would describe the same check differently.

## Decisions

- **New type `assessment`**, filed as `content/sources/okf_assessment_{yyyy}_{mm}_{dd}.md`, one per
  run, never rewritten. Earlier runs are kept so that two can be compared check by check.
- **Layout** — the verdict and the counts per family first, then *Needs attention*, then the three
  mandatory checks (`OKF-CNF-01` to `OKF-CNF-03`), then one table per check family; every row carries
  the check's name from the register next to its ID. Written down in `.claude/rules/sources.md`.
- **Names in the register** — every check gains a short name, copied verbatim into assessments. No
  ID and no wording changes.
- **Log** — `make generate` adds an **Assessment** entry linking the page under the day of the run,
  before that day's releases. The assessment's `description` states the result.
- **`/okf-check` files by default**, and still changes no artifact. Asked for a chat-only result, it
  files nothing.
- **Not a version** — filing an assessment gets no change log entry. Introducing the type does, as
  this change request.
- **First run** — the assessment of the documentation as of this version is filed with this change.
- **The knowledge wiki** the instruction layout comes from gets the same behaviour; that is a change
  to another repository and not recorded here.
- **Assumption:** a second run on the same day is rare enough that a `_2` suffix is sufficient.
