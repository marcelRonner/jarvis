## Request

Requested by the owner on 2026-09-13. The owner found the section *How the artifacts interlink* useful —
it was on the documentation home page of commit `37db765`, served from 2026-08-01 to 2026-09-12 and
dropped when `main` was reset — and asked for it to return, adapted to the Hugo setup. First, the
places that explain the repository were to be checked and each given one audience:

- `README.md` — technical readers setting the repository up; every detail.
- `index.html` at the repository root — ZHAW students who want to know how the internals work
  together; simple language.
- `content/_index.md` — students looking at the documentation for the first time; a brief,
  compressed explanation, the interlinkage, and links to every other explanation.

## Analysis

As of 2026-09-13, the explanation was spread thinly: `README.md` covered the build but not
prerequisites, deploy secrets, the change workflow or troubleshooting, and still named a
`make instructions` target that had become `make generate`; `index.html` said one sentence before the
raw instructions; `content/_index.md` held a welcome line and the artifact list, which gave 14 user
stories where there are 16.

The recovered section assumed MkDocs: review rules sent the reader to edit `mkdocs.yml` navigation,
and it named checks — navigation coverage, story-map coverage, activity-label matching — that the
current `make build` does not perform.

## Decisions

- **Home page** gains *What this is*, *How the artifacts interlink* and *Learn more*; the artifact
  list stays, with the story count corrected to 16 and its User Stories link pointing at the section.
- **Interlinkage, adapted:** the derivation chain adds the change request, entities, actors and the
  log; the chain is stated to be recorded in `sources:`; the join keys add source ids; the review
  rules drop navigation edits, which no longer exist, and end with a change request, a change log
  row and `make build`; the closing line claims only what `make build` checks.
- **Landing page** becomes a plain-language explainer — the five parts, how a change flows, why the
  order matters, the metadata on every page, where the idea comes from — and keeps the generated
  instructions, folded away at the end.
- **README** becomes the complete technical reference: where to start, layout, setup with versions,
  commands, the change workflow, the documentation model, the instructions, OKF with the lint codes,
  the site build, diagrams, deploy and troubleshooting.
- **Links** between the three use their published addresses, so they work on the site, on GitHub and
  in the landing page alike.
